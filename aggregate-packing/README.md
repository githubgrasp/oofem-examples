# Periodic aggregate packing of an RVE

A periodic packing of ellipsoidal aggregates inside a cubic representative
volume element (RVE), generated with OOFEM's stand-alone `aggregate` tool.
The tool reads a short control file, samples an aggregate size distribution
from a sieve (grading) curve, and drops the aggregates into the box one by
one with a trial-and-error placer that rejects any overlap. The result is a
`packing.dat` inclusion list and a ParaView-loadable `packing.vtu` surface.
This is the starting point for a mesoscale concrete model, where the
aggregates are later coupled with a mesh to build a full OOFEM analysis.

## Referenced by

- 2026-08 Blog: https://petergrassl.com/blog/aggregate-placement/

## What it does

`aggregate` places non-overlapping inclusions into a rectangular box:

1. From `dmin`, `dmax` and a target volume fraction it builds a
   Fuller-style sieve curve and samples
   a list of aggregate sizes, largest first.
2. Each aggregate is given a uniformly random orientation and a random position,
   then tested against every aggregate already placed. On overlap it retries,
   up to `maxiter` times, before being skipped.
3. With periodic boundaries, an aggregate that crosses a face is
   copied to the opposite face, so the packing tiles seamlessly
   in all three directions.

Reproducibility comes from a fixed RNG seed and a portable sampler, so the
same control file always yields the same packing.

## The model

A 50 mm cubic, fully periodic RVE. For this illustration, the seed is chosen so the largest
aggregates sit clear of the boundaries (nicer to visualise).

| directive        | value                                  | meaning                                        |
|------------------|----------------------------------------|------------------------------------------------|
| `#@box`          | `3 0.05 0.05 0.05`                     | 3D box, 50 mm side length                       |
| `#@periodicity`  | `3 1 1 1`                              | periodic on all three axes                      |
| `#@seed`         | `8`                                    | RNG seed (fixes the packing)                    |
| `#@maxiter`      | `1000`                                 | max trial placements per aggregate              |
| `#@grading`      | `dmin 0.005 dmax 0.020 fraction 0.3`   | 5–20 mm aggregates, target volume fraction 0.3  |
| `#@output`       | `packing.dat`                          | inclusion-list output                           |
| `#@vtu`          | `packing.vtu`                          | ParaView surface output                         |

The default aggregate shape is `ellipsoid` (random aspect ratio, with
`sx ≤ sy ≤ sz` and `sx/sz ∈ [0.5, 1]`); add `shape sphere` to `#@grading`
for spheres instead.

## What comes out

With this seed the placer seats **29 aggregates**. `packing.dat` holds 54
`ellipsoid` lines. The 29 aggregates plus 25 periodic ghost images of the
ones that straddle a boundary; real and ghost copies share the same id.

The **actual** aggregate volume fraction is **0.150**, about half the target
`fraction 0.3`. This is expected, since the grading curve
is truncated at `dmin = 5 mm`, so every aggregate finer than 5 mm is left out
and implicitly attributed to the mortar matrix. The `fraction` parameter sets
the nominal (untruncated) content. The tool prints the achieved fraction and
a spatial-uniformity diagnostic at the end of the run.

## Reproduce

With the public Docker image (no compilation needed):

```bash
git clone https://github.com/githubgrasp/oofem-examples.git
cd oofem-examples/aggregate-packing
docker run --rm -v "$PWD":/work ghcr.io/githubgrasp/oofem-public:latest bash run.sh
```

`:latest` always points at the current OOFEM build and may evolve. For the
exact image used to produce the figures in the linked blog post, replace
`:latest` with the per-example tag:
`ghcr.io/githubgrasp/oofem-public:aggregate-packing`.

Or, with the `aggregate` tool already on your `PATH`:

```bash
cd oofem-examples/aggregate-packing
bash run.sh
```

Across different math libraries the output text may differ in the last digit
of a coordinate or angle; the packing (aggregate count, sizes, positions) is
otherwise identical.

## Outputs

| file          | content                                                        |
|---------------|----------------------------------------------------------------|
| `packing.dat` | inclusion list — one line per aggregate (and per ghost image)  |
| `packing.vtu` | tessellated aggregate surfaces for ParaView                    |

`packing.dat` is committed as a small, deterministic precomputed result so
the packing can be inspected without running the tool; `packing.vtu`
(regenerated by `run.sh`) is not committed.

### `packing.dat` format

A line-oriented text file: three metadata comment lines, then one record per
inclusion.

```text
# packing v1
# box 0.05 0.05 0.05
# periodicity 1 1 1
ellipsoid 1 centre 3 <cx> <cy> <cz> angles 3 <phix> <phiy> <phiz> radii 3 <sx> <sy> <sz>
ellipsoid 2 ...
```

`centre` is the aggregate centre, `angles` are the intrinsic Euler angles
(Rz·Ry·Rx) of its orientation, and `radii` are the three semi-axes. With
`shape sphere` the record collapses to `sphere <id> centre 3 ... radius <r>`.
This is the same format the downstream generator and converter consume to
seed a node mesh and classify material regions.

### Viewing `packing.vtu`

```bash
paraview packing.vtu
```

Colour by the `id` cell-data array to distinguish individual aggregates, or
threshold on `kind` (0 = ellipsoid surface). The VTU includes the periodic
ghost images by default (so the packing visibly tiles); a `ghost` cell array
tags them (0 = real, 1 = periodic image), so you can `Threshold` on it to hide
or isolate the copies. Add `#@vtughosts 0` to `control.in` to omit the images.

## Further reading

The generation method, poly-dispersed ellipsoids sized from a Fuller grading
curve divided into sieve intervals, placed by random sequential addition with
an ellipsoid-ellipsoid separation test, follows:

> P. Grassl and A. Antonelli. *3D network modelling of fracture processes in
> fibre-reinforced geomaterials.* International Journal of Solids and
> Structures, vol. 156–157, pp. 234–242, 2019.
> [DOI](https://doi.org/10.1016/j.ijsolstr.2018.08.019)

Implementation details, 2D disk packing, fibre placement, spherical
aggregates, the overlap test (Wang et al. 2001, evaluated via the equivalent
Alfano–Greer eigenvalue form), and the full `#@` directive reference — are in
the `aggregate` user manual shipped with the OOFEM source
(`src/aggregate/doc/user_manual.md`) in the githubgrasp fork.
